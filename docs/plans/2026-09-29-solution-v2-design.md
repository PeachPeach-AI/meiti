## 二、架构决策（v2）

```
┌─ 便携版 EXE（用户提供，不在此仓库维护）──────────────┐
│  启动时优先加载 E:\...\60smartStore\hot-update\      │
│  缺失则回退自带静态资源；Ctrl+R / 重启即热载          │
└──────────────┬───────────────────────────────────┘
               │ file:// 或 http 静态加载
┌──────────────▼───────────────────────────────────┐
│  hot-update/（本仓库唯一活跃代码，gitignore）       │
│  smartstore-desktop.html   渲染层：字符串模板+事件委托 │
│  assets/app.css            紧凑工具风样式（已定稿）    │
│  assets/data.js            样例数据 window.SS（契约层）│
│  assets/core/ss-core.js    ★业务内核：纯函数，可单测   │
│                            window.SSCore / module.exports 双挂载 │
└──────────────┬───────────────────────────────────┘
               │ 后置：EXE 注入本地 API（HTTP 127.0.0.1）时，
               │ core 内的 service 接口换实现即可，形状与 9-23 计划的 REST 同形
┌──────────────▼───────────────────────────────────┐
│  tests/core/*.test.mjs  node:test 单测（git 跟踪）   │
│  docs/plans/*.md        决策与实施记录（git 跟踪）    │
└──────────────────────────────────────────────────┘
```

**四条架构原则：**

1. **渲染层零构建**。hot-update 保持纯 HTML/CSS/JS + `<script>` 顺序加载，不做打包、不引框架 —— 这是热更新路线（改完 Ctrl+R 生效）的 existence 条件。
2. **业务内核纯函数化**。凡属计算（聚合、诊断、生成、合规校验）一律进 `assets/core/`，禁止触碰 DOM；渲染层只消费其返回值。core 文件双挂载（浏览器 `window.SSCore` / Node `module.exports`），因此 `node --test` 可直接单测。
3. **数据契约稳定**。视图只经 `window.SS` 读数（既有约定不变）；缺失指标一律 `null`，界面显示「暂无数据/未授权」，绝不用估算值冒充。
4. **能力走适配层**。真实采集、AI 生成、ASR 都定义成接口 + 样例实现，样例实现保证断网可演示，真实实现后置（EXE 侧或云端），业务层不得直接依赖它们。

**四条产品硬口径（继承 9-23 计划，写成测试）：**

1. 缺失数据必须标记「暂无数据/未授权」，不得用估算值冒充真实数据。
2. 每条诊断结论必须能追溯到具体数据/作品/内容特征（`evidence` 非空）。
3. 表现与时间/形式之间只表述相关，不表述因果。
4. 默认分析最近 30 条作品；不足 30 条时分析全部并如实展示样本量。
